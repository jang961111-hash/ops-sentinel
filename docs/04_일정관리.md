# 일정관리 — Ops Sentinel (애자일 스프린트, 밤샘 가능 기준)

기준 시각: 2026-08-08 22:38 KST 시작. 마감 유연(교수 승인) → P0을 최우선 완료해 언제든 제출 가능한 상태를 유지하며 이후 반복.

## 스프린트 개요

| 스프린트 | 범위 | 목표 산출물 | 완료 시 태그 |
|---|---|---|---|
| Sprint 0 (~30분) | 프로젝트 초기화, 엔티티, Repository | 컴파일 되는 스켈레톤 | `v0-skeleton` |
| Sprint 1 (~90분) | 지표 시뮬레이터 + 규칙엔진 + Incident 생성 + 동시성 제어 | 이상탐지 핵심 플로우 동작 | `v1-core-flow` |
| Sprint 2 (~60분) | AOP 감사로그 + 예외처리 + Controller + Swagger | API로 전체 시나리오 재현 가능 | `v2-api-complete` |
| Sprint 3 (~40분) | MyBatis 집계 + Actuator 커스텀 헬스체크 | 분석/운영 엔드포인트 완성 | `v3-analytics` |
| **→ 이 시점이 P0 완료, 제출 가능 최소 버전** | | | **`v-submittable`** |
| Sprint 4 (~40분) | OpenAI API 연동 (판단근거 요약) | AI 요약 기능 동작 | `v4-ai-summary` |
| Sprint 5 (~30분) | JWT 최소 구현 | 관리자 엔드포인트 보호 | `v5-auth` |
| Sprint 6 (~40분) | 테스트 코드 (동시성 재현 + 단위테스트) | 테스트 그린 | `v6-tested` |
| Sprint 7 (선택, ~60분) | Docker Compose, 정적 대시보드 | 원커맨드 실행, 시각화 | `v7-polish` |
| Sprint 8 | 문서화 마무리 + PDF용 캡처 + PPT 발표자료 | 제출 패키지 완성 | `v-final-submit` |

## 체크포인트 원칙

- 매 스프린트 종료 시 `git tag` — 이후 스프린트에서 문제 생기면 언제든 직전 태그로 롤백해 "제출 가능 상태"를 잃지 않는다.
- Sprint 3까지 끝나면(P0) 그 자체로 제출 가능한 완결 프로젝트 — 이후는 전부 보너스.
- 각 스프린트 시작 전 5분 이내로 "이번 스프린트에서 뭘 완성할지" 스스로 재확인(스크럼 데일리 축소판).

## 병렬화 가능 지점 (ulw / team 활용 시)

- Sprint 2(Controller/Swagger)와 Sprint 3(MyBatis 집계)는 도메인이 겹치지 않아 병렬 진행 가능
- Sprint 6(테스트)은 Sprint 1~3 완료 직후부터 별도 에이전트가 병행 작성 가능
- Sprint 7(대시보드)은 완전히 독립적 — 언제든 별도로 병렬 진행 가능
