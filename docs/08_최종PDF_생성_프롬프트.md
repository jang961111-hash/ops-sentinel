## 0. 이 PDF의 대전제 (반드시 지킬 것)

> "점수를 가른 것은 쿼리가 아니라 서술이다." — 과거 채점결과 원문
> "AI 시대에 코드 품질은 평준화된다. 구체적 추론·실제 실험·한계의 솔직한 인정이 진짜 차이다."

- 모든 캡처 아래에는 반드시 해설 3줄(무엇을 증명하나 / 읽는 법 / 값 검증)이 붙는다.
- 전면 이미지 PDF 금지 — 본문은 반드시 텍스트로 작성해 선택·검색 가능해야 한다.
- 성공 화면만 넣지 말고, 실패·예외·검증 화면도 반드시 포함한다.
- "의견·개선사항" 섹션은 공식 요구사항이며 절대 누락하면 안 된다.

### [3] 본문 — 아래 순서 그대로, Ops Sentinel 실제 프로젝트 문서 기반

1. **기획 배경** — `docs/01_PRD_기획명세서_최종본.md`의 "왜 이 주제인가"를 근거로 서술. SK AX×대신증권 사례를 반드시 근거자료집(`docs/07_배경조사_근거자료집.md`)의 1차/2차 출처와 함께 인용 — "카더라"가 아니라 출처를 명시한다.
2. **아키텍처 결정(ADR)** — PRD의 "3-1. 아키텍처 결정" 섹션(모듈러 모놀리식 채택 근거, MSA/AWS 배포를 왜 안 했는지)을 그대로 서술. 시스템 아키텍처 다이어그램(`docs/03_시스템아키텍처.html`을 캡처하거나 재작성)을 삽입.
3. **도메인 모델 & API 스펙** — `docs/02_API_기능명세서.md` 기반. 실제 Swagger UI 캡처(엔드포인트 전체가 보이는 화면) + 각 엔드포인트 요청/응답 캡처(성공 케이스 + 실패/검증 케이스 최소 1개씩).
4. **핵심 시나리오 재현** — "지표 이상 발생 → Incident 자동 생성 → 조치 기록 → AI 요약" 전체 흐름을 curl/Swagger 캡처로 처음부터 끝까지 순서대로 보여준다. 각 단계 캡처마다 "무엇을 증명하나" 해설 필수.
5. **동시성 제어 검증** — 동시 요청 테스트 결과 캡처(터미널, 다크 테마) + 값 검증(몇 건 요청했는데 몇 건만 성공했는지 숫자로 계산해서 맞는지 서술).
6. **AOP 감사로그 검증** — 성공 케이스와 의도적 실패 케이스 둘 다 캡처, AuditLog에 둘 다 남아있는지 확인하는 화면.
7. **Actuator 헬스체크 검증** — UP→DOWN→UP 전환을 실제로 재현한 캡처 (CRITICAL Incident 유발 → DOWN 확인 → resolve → 다시 UP).
8. **OpenAI 연동 검증** — 정상 요약 생성 캡처 + (가능하면) API 강제 실패시켜서 폴백 문장이 나오는 캡처 둘 다.
9. **Git/협업 워크플로우 증빙** — GitHub 이슈 목록 캡처, PR 목록(머지된 것) 캡처, `git log --oneline --graph` 캡처. 커밋 컨벤션·이슈연동·PR템플릿을 실제로 지켰다는 걸 화면으로 증명.
10. **테스트 결과** — 전체 테스트 실행 결과(통과 건수), 커버리지 있으면 포함.
11. **근거자료 요약** — `docs/07_배경조사_근거자료집.md`의 핵심 3~4개 출처(FINOS, Google SRE, AIOps 논문, SK AX 기사)를 한 페이지로 요약, 왜 이 설계를 택했는지 학술/산업 근거와 연결.

### [4] 의견·개선사항 (4개 소제목 고정, 절대 누락 금지)

1. **막혔던 부분 & 해결 과정** — ralph 진행 중 실제로 있었던 문제를 구체적으로 쓴다 (예: `management.endpoints.web.exposure.include` 누락으로 HealthIndicator가 실제로는 노출 안 되던 문제를 발견하고 고친 것, flaky test 재현·검증 과정 등). "에러가 났다"가 아니라 "무엇이 무엇을 삼켰는지" 구체적으로.
2. **왜 이 방법을 선택했나** — 모듈러 모놀리식 vs MSA, 규칙엔진+LLM설명 분리 설계, JPA/MyBatis 분담 근거를 대안과 비교하며 서술.
3. **개선 사항 / 코드 품질 의견** — 지금 코드의 한계를 스스로 지적 (예: 실제 인프라가 아닌 시뮬레이션 데이터라는 점, AOP가 로깅 관심사 하나뿐이라면 그 점, 테스트 커버리지 등).
4. **한계의 솔직한 인정** — SK AX 1차 소스(공식 뉴스룁)를 세션 제약상 직접 캡처하지 못하고 언론 교차검증으로 대체했다는 점 등, 확인 못 한 것은 확인 못 했다고 정직하게 쓴다.

## 5. 캡처 규격

- 해상도 deviceScaleFactor 2 (레티나)
- 브라우저 캡처: 뷰포트 1440×900, 해당 블록만
- 터미널 캡처: 폰트 16pt 이상, 다크 테마로 통일 (브라우저는 라이트로 통일 — 한 문서 안에서 섞지 않는다)
- 전체 용량 20MB 이하 목표 (넘으면 JPEG 품질 85로 변환)

## 6. 생성 방법

1. Playwright(headless Chromium)로 각 섹션을 HTML로 만들고 `.page { page-break-after: always }`
2. 캡처는 실제로 로컬에서 서버 띄우고 curl/Swagger 스크린샷을 떠서 삽입 — 지어낸 화면 캡처 금지
3. `page.pdf({ format: 'A4', printBackground: true, margin: {...} })`
4. 생성 후 **한글 렌더링을 직접 열어서 눈으로 확인** (□□□ 깨짐 없는지)
5. 페이지 순서는 배열로 명시 (파일명 정렬 의존 금지)
