- **결과를 따로 검증하게 한 구조.** 개발 에이전트와 별도인 리뷰 에이전트 검증(REJECTED → C1~C5 수정 → APPROVED)과, 사전지식 없는 에이전트가 제출 zip을 풀어 채점하는 콜드스타트 채점을 거쳤다. 동시 40건 결함은 두 번째 방식에서만 나왔다.
- **작업 단위가 추적 가능했다.** 스프린트마다 태그(13개), 이슈 → 브랜치 → PR → squash 머지, CHANGELOG에 수정 전후 수치를 남겼다. 당시 CHANGELOG가 "150건이면 409 91건, FAIL 감사 0건"을 적어 둔 덕분에 2026-09 재측정 결과와 숫자를 맞춰 볼 수 있었다.
- **사후 보완을 재현 테스트부터 쌓았다.** PR #48의 결함 6건(락 안 AI 호출, 좁은 풀 감사 교착, fast path, 리뷰 MED 2건, 긴 에러 메시지 감사 유실)은 모두 재현 테스트로 수정 전 실패를 먼저 확인한 뒤 고쳤다(5건은 실패하는 테스트를 별도 커밋으로 먼저 남겼다: `3984014`, `4ec2251`, `3407002`).

## Problem — 아쉬운 것

- **README가 측정하지 않은 것을 단정했다.** "감사로그 100% 기록"은 동시 150건에서 38~39%였고, "풀 증설로 해결"은 풀 60에서도 150건이면 붕괴했다. CHANGELOG에는 한계가 적혀 있었는데 README 요약에서 빠졌다.
- **테스트가 위험한 경로를 거치지 않았다.** 테스트는 OpenAI 키를 빈 값으로 고정해 AI 호출 경로를 한 번도 타지 않았다(`AiSummaryService` 브랜치 커버리지 2/12). 40건 동시성 테스트는 예외가 없는지만 봤고 감사 건수는 세지 않았다. 그래서 락 안 AI 호출을 CI가 잡을 수 없었다.
- **증상 완화를 해결로 기록했다.** 2026-08-09에는 500을 없애는 데 집중해 재시도 예외 목록을 늘리고 풀을 60으로 올렸다. 커넥션이 왜 부족한지(OSIV, 락 안 REQUIRES_NEW)는 묻지 않았다.
- **CI가 없었다.** 테스트 46건이 있었지만 자동 실행되지 않았다. CI를 붙인 첫 실행에서 Linux 전용 시각 정밀도 버그가 바로 나왔다.
- **공개 레포 위생.** 교육과정 내부 정보(강사 실명·공지 인용·교육생 고유번호가 적힌 제출 PDF)와 제3자 뉴스룸 캡처가 공개 트리에 있었다. 2026-09에 현재 트리에서는 뺐지만 과거 커밋 이력에는 남아 있다.
- **AI로 개발했다는 사실을 README에 쓰지 않았다.** 지시문 원문은 `docs/`에 있었지만 설명이 없었다.
